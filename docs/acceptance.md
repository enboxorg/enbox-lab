**Enbox Lab — assumptions and acceptance checklist v0.3**

Companion to the [current plan](./plan.md), refined during P0 on 2026-09-20. This is a verification ledger, not a list of passed tests. Source evidence refers to Enbox `05b41776e92bd1f42462726d7a7d4bb2a0fcb9de`. Recheck against the selected SDK revision.

**Status and use**

The user has accepted the product direction, isolation requirement and signed-publication persistence design. Those decisions do not establish runtime correctness. Verification remains pending except for the platform-scoped evidence recorded below; source facts are listed separately at the end.

For each row, implementation records: status (`pending`, `proved`, `disproved`), exact artifacts/platform, command or manual procedure, evidence path, and resulting design decision. A failed assumption gets an explicit replacement decision and new proof; it cannot silently become an unsupported feature while the release is called complete. Optional catalog capabilities can be unsupported, but the required reference configuration must satisfy the goal.

Keep stage-specific evidence under each ID: passing a P0 subset does not mark a later lifecycle or soak obligation proved. New planning defaults remain proposals until their gate passes. The plan's four P0 spikes produce runnable proof artifacts and decisions; P1 packages ownership/commands, P2 delivers the usable private-note lab, P3 completes scenarios/UI, and P4 qualifies the release.

**B. DID service**

| ID / stage | Assumption or obligation | Required proof and failure handling |
| --- | --- | --- |
| A06 / P0 | The gateway fronts a genuinely private DHT. | Pinned upstream configuration uses only private testnet bootstrap. Real signatures validate; did:jwk delegates remain self-resolving. A cold client in lab B cannot resolve lab A's newly generated DID through B's service. Exercise the DHT path, not only a populated resolver/relay cache. |
| A07 / P0 | Acknowledged publications survive crashes. | Crash before/after upstream acceptance, journal commit and response; restart adapter/testnet independently. Every acknowledged packet is restored or superseded by a newer accepted one. Disk-full/journal failure never returns durable success. Establish the pinned relay's PUT success semantics separately from network availability. Startup validates/restores durable state before admitting client publications. Record ambiguous unacknowledged outcomes; do not promise exactly-once publication. |
| A08 / P0 | Retries and newer versions cannot corrupt restoration. | Concurrent updates, identical retries, stale writes, conflicting equal versions and replay racing a new update preserve pinned upstream semantics. Client writes, replay and maintenance use one per-key serialization path. Check the durable latest version before forwarding so a recreated upstream cannot admit a regression. Compare exact signed bytes; retain integer precision. Invalid packets never become restorable journal state. Replay uses standard PUT, not invented documents. |
| A09 / P0,P4 | DIDs remain available during long sessions. | Verify periodic re-publication calls and latest-version selection in P0; qualification includes a run beyond actual upstream retention with cold/network-only reads and wallets locked. Test wake/reconnect after a long pause. Confirm expiry of relay/client caches separately from DHT item expiration. |
| A10 / P0 | Every DID operation uses its instance's network. | Audit and exercise vault creation/recovery, identity updates, agent resolve/publish, connect verification, server authorization/forwarding and page/SW DRL fetch. One immutable DID configuration reaches every factory/collaborator; page and worker load actor-specific public bootstrap before Enbox initialization. Concurrent lab configs/cache instances remain independent. No global process shim or production default/validation weakening. |
| A11 / P0,P3 | Published endpoints eventually become effective routes. | Update a DID, verify a fresh signed resolution, then verify actual connections after supported routing refresh/cache expiry. Record pending state and real cache TTLs. In the unavailable-DID case, fail only the DID route/upstream while DWN gateway routes stay available; distinguish cold failure from cache-assisted success. A successful PUT alone does not prove every actor has switched; assignment is not an atomic migration or remote deletion. |

**E. Controller, data and tracing**

| ID / stage | Assumption or obligation | Required proof and failure handling |
| --- | --- | --- |
| A22 / P1 | Reconciliation is safe after partial work. | OS-backed exclusive controller lock; stale structural revision and conflicting idempotency payload tests. Same-key/same-payload retries return the same job. Crash during container/identity/endpoint creation; reconcile actor state or enter needs-reconciliation rather than blindly retrying business actions. Recovery never adopts resources from another owner or silently resets corrupt state. Layout-only edits do not invalidate structural commands. |
| A23 / P1,P3 | Saved state, replacement and recipes are distinct. | Reopen with existing volumes; saved-port collision fails clearly. Version replacement uses fresh storage. Recipe roundtrip creates fresh identities and origins, contains no secrets, and accepts no executable scripts/host mounts. Unknown schema versions fail without erasing existing data. |
| A24 / P0,P2,P3 | Observation preserves protocol behavior. | Enabled/disabled observer paths yield the same signed CIDs and payload bytes. Exercise streams, HTTP errors, WS ordering/acks, reconnect and backpressure. The observer has bounded work/memory and does not change DWN authorization/results. |
| A25 / P2,P3 | Correlation and playback do not invent causality. | Interleave tenants, records, updates, retries and producers sharing RPC request IDs. Match tenant/message/connection scope and producer epochs; uncertain links stay unknown. Playback triggers zero network mutations. Measured durations use appropriate clocks. |
| A26 / P2,P4 | Trace loss and storage limits are explicit. | Disconnect/overflow collector, resume cursors, rotate journal and exhaust trace storage. Expired cursors return an explicit gap and fresh snapshot. Keep job results/assertion verdicts separately durable; mark gaps and make dependent assertions inconclusive. Trace quotas never prune DID publications or actor data. Active/last-failed evidence is not silently rotated away; deleted retained evidence has an evidence-expired marker. |
| A27 / P2,P4 | Redaction and resource budgets survive real use. | Seed recognizable fake secrets; inspect all trace/export/log surfaces for leakage. Measure fixture startup, idle memory/CPU, disk and burst rendering; freeze documented limits/default retention from results. Large traces stay navigable. No performance or minimum-laptop claim is accepted without measurement. |
| A28 / P1,P3 | UI and CLI share complete command coverage. | Exercise every UI mutation through its typed CLI operation, including wallet/identity/session management, endpoints, actor lifecycle and scenario controls. Secrets never enter durable command payloads. Test job waiting, stable JSON errors and nonzero run-verdict exits. Submission acceptance cannot be mistaken for scenario success. |
| A29 / P1,P2 | Control and protocol traffic have independent lifetimes. | Disconnect the host-initiated controller/gateway command channel while existing authorized app traffic and gateway DID maintenance continue. Mark active runs interrupted and observations stale; reconnect reconciles jobs and producers. Stop the gateway separately and report its shared impact. Containers do not need callbacks to arbitrary host services; actor channels cannot access another actor or controller credentials. |

**Source findings that changed this revision**

- [BEP44](https://www.bittorrent.org/beps/bep_0044.html#expiration) describes expiry and re-announcement of signed values without the signing key. The accepted persistence design therefore includes ongoing refresh, not just replay at startup.
- [Identity deletion](https://github.com/enboxorg/enbox/blob/main/packages/agent/src/identity-api.ts#L211) removes the identity registration; the lab must not label that operation a complete key/data purge.
- [Connect approval](https://github.com/enboxorg/enbox/blob/main/packages/agent/src/connect-approval.ts#L80) currently defaults to one-hour grant lifetimes. [Auth monitoring](https://github.com/enboxorg/enbox/blob/main/packages/auth/src/auth-manager.ts#L442) includes polling and renewal behavior. Retain normal SDK behavior; avoid adding record-query polling.
- [Server configuration](https://github.com/enboxorg/enbox/blob/main/packages/dwn-server/src/config.ts#L263) defaults endpoint forwarding and protocol delivery off and caches delivery endpoints. These are explicit scenario inputs, not implicit capabilities of every running node.
- [Server construction](https://github.com/enboxorg/enbox/blob/main/packages/dwn-server/src/dwn-server.ts#L267) and forwarding accept resolver injection. Agent/vault publication still needs a complete per-instance configuration audit; historical versions may differ.
- [Localhost resolution](https://www.rfc-editor.org/rfc/rfc6761.html#section-6.3) can bypass configured DNS and [browser secure-context rules](https://www.w3.org/TR/secure-contexts/#localhost) depend on loopback semantics. The Linux proof disproved multi-label `*.localhost` for container Bun 1.3.14 and selected distinct plain-localhost ports with actor-local forwarders.
- [WalletPostMessageTransport](https://github.com/enboxorg/enbox/blob/main/packages/browser/src/dweb-connect-wallet.ts) owns popup origin/source checks and its ephemeral key. [ConnectProvider](https://github.com/enboxorg/enbox/blob/main/packages/connect/src/provider.ts) accepts the real ceremony output for response sealing. These support the proposed page/worker split but do not prove its integration.
- [Enbox PR #1726](https://github.com/enboxorg/enbox/pull/1726) adds immutable per-instance DID DHT configuration through the default agent, auth, anonymous API and browser resolver paths. Current released-server authorization injection is proved below; forwarding, historical builds and the remaining agent/browser runtime audit stay open P0 evidence gates.
- [Playwright service-worker networking](https://playwright.dev/docs/service-workers) distinguishes worker requests and documents interception limitations. Acceptance retains the required worker and supplements browser evidence with gateway/runtime observations.

The execution packet must name the selected canonical-address mechanism; effective generated Compose/network settings; exact Pkarr image and publication/refresh rules; SDK API changes/call-site coverage; page/worker connect split; both qualified DWN artifacts; browser/Docker/CPU platform matrix; real connect/record trace; and executable commands for the gates above. Each remaining P1–P4 row must have a bounded implementation task and acceptance procedure. Schemas include complete UI/CLI command coverage and immutable run locks. Numerical deadlines, capacity and retention defaults must be explicit before final release qualification.

Implementation is proceeding as a stacked pull-request series in the standalone Enbox Lab repository. Only the evidence listed above is claimed; no macOS, complete private-DHT, two-version runtime or end-to-end application qualification is claimed yet.
